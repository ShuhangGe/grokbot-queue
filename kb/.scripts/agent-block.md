## 知识库 {{KB}}/

**不管什么任务，第一件事：读 [`{{KB}}/ROUTE.md`]({{KB}}/ROUTE.md) —— 按问题找条目的路由表。没有例外，没有「如果……才读」。**

> 原先写的是「查询外部事实前才读」。这句话害得一个 agent 完整读完仓库却什么都没找到 ——
> 它的任务不是查外部事实，于是跳过了整个 kb/，而里面装着数千行内容。
> **对 agent 而言，条件路由 ≈ 不可靠路由**：判断「当前是不是 X」时，恰恰还没有 X 里的信息。

> 路由表单独成文件，是因为它是这里唯一无条件要求读的东西。它曾经长在 `INDEX.md` 顶部，
> 而那份索引带着标签段和全部条目摘要，一次 Read 就是十几万字符 —— 「只读顶部」在工具层面
> 做不到：要判断顶部到哪结束，得先读完。

| 文件 | 用途 |
|---|---|
| `{{KB}}/ROUTE.md` | **无条件必读**：按问题找条目，一条目一行、问法并列 |
| `{{KB}}/INDEX.md` | 全部条目 + 摘要 + 新鲜度 + 地基健康度 + 按领域分组（路由表已独立） |
| `{{KB}}/STALE.md` | 待复核：🔴 已过期 · ⚠️ 地基松动 · ⏰ 未来 90 天闹钟 |
| `{{KB}}/GRAPH.md` | 依赖图 + 反向链接 —— **改一条之前先看它的影响面** |
| `{{KB}}/OPEN.md` | 开放问题工作队列 |
| `{{KB}}/index.json` | 机器可读：锚点、标签、时间字段、反向链接 |

**调研任何外部问题之前，先 `node {{KB}}/.scripts/search.mjs "<问题>"`** —— 别的项目可能已经查过，共享层里可能已经有答案。重复调研是这套系统要消灭的第一件事。

三条防损规则：① 引用事实时标注它的 `id` 与 `asserted_at` ② 标 ⚠️ 地基松动的判断**不要直接引用它的结论** ③ 发现有误或已变化**不要直接改**，走 supersede：`node {{KB}}/.scripts/new.mjs --supersedes <id>`。以上六个产物全部自动生成，永远不要手改。完整规则见 `{{KB}}/README.md`。Claude Code 可用 `/ml` 子命令；其它 agent 直接跑 `{{KB}}/.scripts/` 里的脚本。**起草完直接 commit，commit message 就是摘要（每条一行：id · 一句话 · 会怎么坏）—— 人按摘要把关，不逐条确认；有疑问点名那一条，错了走 supersede。**

**你是这套系统的用户，不是旁观者。** 用的过程中卡住了、缺什么、觉得哪条规则不对 —— 一行命令记下来，不要在对话里说完就算，说完就丢了：

```
node {{KB}}/.scripts/feedback.mjs --kind bug|friction|missing|wrong|question --doing "当时在做什么" "一句话说清楚"
```

只记**真的挡住你**或**你有具体更好做法**的；一条一个文件；`--doing` 必填，同一条意见附上任务背景才分得清是普遍的还是特定场景的。提之前先 `node {{KB}}/.scripts/feedback.mjs --list` 看有没有人提过 —— 被拒的也留着，带着原因。

**任务收尾时复盘一句**：`node {{KB}}/.scripts/feedback.mjs --kind review --verdict helped|neutral|hindered --doing "这次的任务" "kb 帮到/没帮到了什么"`。这不是抱怨渠道，是数据 —— 抱怨只在坏的时候出现，复盘在好的时候也出现，比例才是「这工具有没有用」的答案。
