## 你在 {{LAYER}} 层 —— 这里的每一条对所有项目可见

**不管什么任务，第一件事：读 [`{{KB}}/ROUTE.md`]({{KB}}/ROUTE.md) —— 按问题找条目的路由表。没有例外，没有「如果……才读」。**

这不是某个项目的知识库。它是**跨项目共享的那一层**：登记在这台机器上的每个项目都透过分层看到这里的条目，它们的判断可以 `depends_on` 这里的事实 —— 这里一条事实过期，下游所有项目的判断同时被标「地基松动」。所以：

- **只放跨项目成立的。** 某个项目专属的东西回那个项目的 `kb/` 里。
- **`owner` 必填。** 上层被多个项目共享，过期了得知道找谁。
- **按主题分文件夹**（如 `agent/`）：一个主题一个 owner，fact / judgment / reference 混放，各自的 `type` 字段带时间语义。

| 文件 | 用途 |
|---|---|
| `{{KB}}/ROUTE.md` | **无条件必读**：按问题找条目，一条目一行、问法并列 |
| `{{KB}}/INDEX.md` | 全部条目 + 摘要 + 新鲜度 + 按领域分组（路由表已独立） |
| `{{KB}}/STALE.md` | 待复核：🔴 已过期 · ⚠️ 地基松动 · 🟠 出处已变动 · 📄 未处理的调研报告 |
| `{{KB}}/GRAPH.md` | 依赖图 + 反向链接 —— **改一条之前先看它的影响面**（这里的影响面是所有项目） |
| `{{KB}}/index.json` | 机器可读 |

**调研流程**（在主题文件夹里开 session 时）：

1. **先搜全库**：`node {{KB}}/.scripts/search.mjs "<问题>"` —— 三层 + 所有项目。别的项目可能已经查过。重复调研是这套系统要消灭的第一件事。
2. 调研。原始笔记、来源、过程写成报告存 **`<主题>/research/<日期>-<主题>.md`**（不需要 front-matter，随便写）。`research/` 里的文件不算条目，算**文档** —— 它是条目的出处。
3. 提炼成条目：`node {{KB}}/.scripts/new.mjs --dir <主题> --owner <你> --from <主题>/research/<那份报告>` 。**条目只装会过期的断言**，不是报告的复制。报告改了，条目会被标「出处已变动」。
4. `node {{KB}}/.scripts/build-index.mjs` → **直接 commit，commit message 就是这批的摘要**（每条一行：id · 一句话 · 会怎么坏）。人按摘要把关，不逐条确认；有疑问点名那一条，错了走 supersede。这里每条对所有项目可见，所以摘要要写清「为什么跨项目成立」。

三条防损规则：① 引用事实标注 `id` 与 `asserted_at` ② 标 ⚠️ 地基松动的判断**不要直接引用它的结论** ③ 发现有误**不要直接改**，走 supersede：`node {{KB}}/.scripts/new.mjs --supersedes <id>` —— 这里一条被改，所有项目都要跟着重看，原地改会让它们无从追溯。产物全部自动生成，永远不要手改。Claude Code 可用 `/ml`；其它 agent 直接跑 `{{KB}}/.scripts/` 里的脚本。

**你是这套系统的用户，不是旁观者。** 卡住了、缺什么、哪条规则不对 —— 一行记下来：`node {{KB}}/.scripts/feedback.mjs --kind bug|friction|missing|wrong|question --doing "当时在做什么" "一句话"`。只记真的挡住你或有具体更好做法的。**任务收尾复盘一句**：`--kind review --verdict helped|neutral|hindered`。
